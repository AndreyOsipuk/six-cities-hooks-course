# Критерии проверки проекта

Основа - критерии HTML Academy к проекту «Шесть городов»: базовые (Б) и дополнительные (Д). Номера академии сохранены, чтобы их было легко сверить. Устаревшие критерии переписаны под актуальный стек, наши требования добавлены с номерами Б23 и выше, Д31 и выше.

Как устроено:

- **Базовые критерии (Б)** - обязательный минимум. Пока не выполнены все базовые, дополнительные не засчитываются.
- **Дополнительные критерии (Д)** - качество, детали и полнота.
- **Понимание (П)** - проверяется на защите. Пункт задания (этап, свой хук, пункт M) засчитывается, только если вы смогли объяснить, как он работает.

В колонке «Как проверяется»: **авто** - командой или скриптом, **вручную** - преподаватель смотрит код или приложение, **защита** - на защите при вас.

## Понимание (защита)

Проект защищается на занятии, вживую с экраном. Каждый критерий: **подтверждено** (сами, без подсказок), **частично** (с наводящими вопросами, но рассуждение верное), **не подтверждено**.

| Код | Критерий |
|-----|----------|
| П1 | Объясняет любую строку своего кода: зачем она, что будет, если её убрать |
| П2 | Отвечает на вопросы «П» из [TASKS.md](TASKS.md) по выбранному преподавателем хуку |
| П3 | Воспроизводит вживую баг из своего журнала и объясняет причину своими словами |
| П4 | Вносит небольшую правку в свой код при преподавателе: тест + код |
| П5 | Находит ошибку, внесённую преподавателем в свой хук, через тесты или DevTools, и чинит её |
| П6 | Предсказывает вывод незнакомого фрагмента кода (как в `QUESTIONS.md`) |
| П7 | Сравнивает свою реализацию со встроенным API React 19 (M1, M2, M5, M6, M8): что API делает за вас, что осталось |

**Правило:** если по хуку, который проверялся на защите, не подтверждены П1, П4 или П5 - этот хук не засчитывается в Б28 / Д31.
