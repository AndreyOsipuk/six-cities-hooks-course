# Критерии оценки курсового проекта «Шесть городов: свои хуки»

Проект оценивается по трём уровням: **3, 4 и 5 баллов**. Уровень засчитывается, только если:

1. выполнены все **обязательные условия** (раздел 1);
2. приняты **все хуки** этого уровня и всех уровней ниже (раздел 2);
3. на защите вы **объяснили свой код** (раздел 3).

Хук считается принятым, только если у него закрыты все три пункта: **Ф** (работает), **Т** (покрыт тестом), **П** (вы понимаете, как он устроен). Нет одного пункта - хук не засчитан, даже если код идеальный.

## 2. Хуки по уровням

Параметры в `[квадратных скобках]` берёте из своего варианта.

### Уровень «3» - база

**H1. `useDebouncedValue(value, delay)` - поиск по названию**
- Ф: на главной над списком появляется поле «Search by title». Список фильтруется по названию предложения без учёта регистра, **через `[delay]` мс после последнего ввода**, а не на каждую букву. Поиск работает вместе с сортировкой и сменой города. При смене города поле очищается.
- Т: тест на фейковых таймерах: значение не меняется раньше `[delay]`, меняется после; при частом вводе таймер перезапускается; после размонтирования таймер не срабатывает.
- П: зачем cleanup в эффекте; что будет без него; почему `delay` в зависимостях.

**H2. `useOfferLoader(offerId)` - загрузка предложения без гонок**
- Ф: на странице `/offer/:id` предложение, соседние предложения и отзывы грузятся через этот хук (внутри - ваши thunk-и Redux). При быстром переходе между предложениями (клик по карточкам «неподалёку») **никогда не показывается устаревшее предложение**. Предыдущий запрос отменяется (`AbortController` / `promise.abort()` у thunk). Есть состояния «загрузка», «ошибка», «не найдено» (404).
- Т: тест, где первый запрос отвечает позже второго, - на экране данные второго; тест на отмену при размонтировании.
- П: что такое гонка запросов; покажите её вживую (см. «Как увидеть гонку» в `README.md`); почему отмена в cleanup, а не в обработчике клика.

**H3. `useOutsideClick(ref, handler, isActive)` + закрытие по Escape**
- Ф: меню сортировки закрывается по клику вне него и по клавише Escape. Подписка на `document` есть **только пока меню открыто**.
- Т: клик внутри - не закрывает, снаружи - закрывает; Escape закрывает; после закрытия/размонтирования обработчики сняты.
- П: почему подписка не должна пересоздаваться на каждый рендер, если `handler` - новая функция; как вы это решили (`useRef` с актуальным обработчиком / `useCallback`) и в чём разница.

### Уровень «4» - всё из «3» плюс

**H4. `useYandexMap(containerRef, city, offers, activeOfferId)` - карта на Яндекс Картах**
- Ф: карта Leaflet заменена на Яндекс Карты (JS API 3.0, ключ - в `.env.local`, в репозиторий не попадает, см. `SETUP.md`). Скрипт API грузится **один раз** на всё приложение. Карта создаётся один раз, при смене города меняется центр, при наведении на карточку маркер меняет цвет (на странице предложения - нет, как в ТЗ). При уходе со страницы карта уничтожается.
- Т: тест с подменой (моком) API карт: карта создаётся один раз; при смене `activeOfferId` пересоздаются только маркеры, а не карта; при размонтировании вызывается `destroy`.
- П: почему в `StrictMode` в dev-режиме эффект срабатывает дважды и что было бы с картой без cleanup; почему инициализация карты и обновление маркеров - разные эффекты.

**H5. `usePersistentState(key, initialValue)` - черновик отзыва**
- Ф: текст и оценка в форме отзыва сохраняются в `localStorage` под ключом `[prefix]-draft-<offerId>` и восстанавливаются после перезагрузки. После успешной отправки черновик удаляется. Если открыть то же предложение во второй вкладке и печатать в первой - вторая подхватывает изменения (событие `storage`). Повреждённое значение в `localStorage` не роняет приложение.
- Т: восстановление из хранилища; запись при изменении; битый JSON → начальное значение; реакция на событие `storage`; смена `key` (другой offerId) не утаскивает чужой черновик.
- П: зачем ленивая инициализация `useState(() => ...)`; что произойдёт при смене `key` в вашем коде.

**H6. `usePagedList(items, pageSize)` + `IntersectionObserver` - подгрузка карточек**
- Ф: на главной список показывается порциями по `[pageSize]` карточек, следующая порция появляется, когда пользователь докрутил до конца списка. При смене города, сортировки или поиска показ начинается с первой порции.
- Т: начальная порция; следующая порция при срабатывании наблюдателя (наблюдатель замокан); сброс при смене входного массива; отключение наблюдателя при размонтировании.
- П: почему сброс порции по смене `items` - отдельная задача и как вы её решили (ключ, эффект, вычисление при рендере) и чем эти способы отличаются.

### Уровень «5» - всё из «4» плюс

**H7. `useRecentlyViewed()` - недавно просмотренные**
- Ф: на главной под списком блок «Recently viewed» - последние `[recentCount]` открытых предложений, новые сверху, без дублей. Хранится между перезагрузками. Хук **построен на вашем `usePersistentState`** (композиция хуков), а не копирует его код.
- Т: порядок, отсутствие дублей, ограничение длины, переживает перезагрузку.
- П: что такое композиция хуков; почему два компонента с этим хуком на одной странице показывают одно и то же (или нет - и как починить).

**H8. `useOnlineStatus()` на `useSyncExternalStore` + замер производительности**
- Ф: при пропаже сети (DevTools → Offline) сверху появляется плашка «Нет соединения», при возврате исчезает. Реализовано через `useSyncExternalStore`, а не `useEffect` + `useState`.
- Ф: файл `PERF.md` - замер в React DevTools Profiler главной страницы **до и после** оптимизации (`memo`, `useMemo`, `useCallback`), с цифрами и скриншотами. Оптимизация только там, где замер показал лишние рендеры.
- Т: тест хука с переключением `navigator.onLine` и событиями `online`/`offline`.
- П: чем `useSyncExternalStore` лучше связки «эффект + состояние» для внешних источников; почему `useCallback` без `memo` у дочернего компонента часто бесполезен.

## 3. Защита (обязательна, 15-20 минут, вживую с экраном)

На защите **не нужно** ничего рассказывать по слайдам. Будет так:

1. **Объяснение своего кода.** Я открываю любой ваш хук и показываю на любую строку: зачем она? что будет, если её убрать? Не смогли объяснить - хук не засчитан (П = 0).
2. **Живая правка.** Небольшое изменение в вашем коде при мне, без подсказчиков: например, «пусть поиск срабатывает и по типу жилья», «закрывай меню ещё и при скролле», «сделай, чтобы черновик жил 1 час».
3. **Сломай и почини.** Я ломаю что-то в вашем хуке (убираю cleanup, зависимость, отмену запроса). Нужно: (а) сказать, какой тест упадёт, и запустить, (б) показать баг в браузере, (в) починить.
4. **Предскажи вывод.** Небольшой фрагмент кода с `console.log` в рендере и эффектах - нужно сказать порядок вывода без запуска.

Пункты 3 и 4 показывают, понимаете ли вы хуки вообще, а не только свой код. Провал пунктов 3-4 снижает итог на один уровень.
