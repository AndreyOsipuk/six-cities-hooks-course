# Задание курсового проекта «Шесть городов: свои хуки»

Что такое само приложение «Шесть городов» - страницы, их содержимое, сервер - описано в [PROJECT.md](PROJECT.md). Здесь - что именно нужно сделать в курсовом.

У каждого пункта три части:

- **Ф** - что должно работать в приложении;
- **Т** - что должно быть покрыто тестами;
- **П** - что вы должны уметь объяснить про свой код.

### Часть 1. Обновление стека и базовые хуки

**H0. Обновление стека - первый PR, до всех хуков**
- Ф: проект переведён на актуальные версии: React 19.3, React Router 8, Redux Toolkit 2, Vite 8, Vitest 5, TypeScript 7.0 (проверка типов через `npm run typecheck`, см. `SETUP.md`), ESLint 10, `eslint-plugin-react-hooks` 7 в flat config с правилами React Compiler. Пакет `react-router-dom` удалён, импорт из `react-router`. Node.js 24+. Конфиг линтера академии - `eslint-config-htmlacademy` 11 в flat config.
- Ф: приложение работает как раньше, все старые тесты зелёные, `npm run lint` без ошибок. Всё, что новый линтер нашёл в старом коде (`set-state-in-effect`, `refs` и другие), - исправлено, а не отключено.
- Ф: в описании PR - список ломающих изменений, с которыми вы столкнулись, и как их решили (по одному-два предложения на пункт). Обновление делается **по шагам**: отдельный коммит на каждую библиотеку.
- П: что изменилось в React 19 для вашего кода (`ref` как обычный проп, `forwardRef`, `<Context>` как провайдер, типы `ReactNode`/`JSX`); почему React Router 8 требует React 19.2.7+; что нашёл новый линтер и почему это были ошибки; почему в проекте два пакета TypeScript и что делает каждый.

**H1. `useDebouncedValue(value, delay)` и `useDebouncedCallback(fn, delay)` - поиск по названию**
- Ф: на главной над списком появляется поле «Search by title». Список фильтруется по названию без учёта регистра **через `[delay]` мс после последнего ввода**, а не на каждую букву. Поиск работает вместе с сортировкой и сменой города.
- Ф: `useDebouncedCallback` возвращает функцию с методами `cancel()` и `flush()`. По Enter поиск срабатывает сразу (`flush`), по кнопке очистки поля - отменяется (`cancel`). Вызов всегда использует **последнюю** версию `fn`, даже если она поменялась во время ожидания.
- Т: фейковые таймеры: значение не меняется раньше `[delay]`; частый ввод перезапускает таймер; `flush` и `cancel`; после размонтирования ничего не срабатывает; смена `fn` во время ожидания - вызывается новая.
- П: чем «отложенное значение» отличается от «отложенной функции» и когда что брать; зачем cleanup; почему `fn` хранится в `ref`, а не в зависимостях.

**H2. `useOfferLoader(offerId)` - загрузка предложения без гонок**
- Ф: на странице `/offer/:id` предложение, соседние предложения и отзывы грузятся через этот хук (внутри - ваши thunk-и Redux). Возвращает `{ status, offer, nearby, reviews, error, retry }`, где `status` - `'idle' | 'loading' | 'success' | 'error' | 'not-found'`.
- Ф: при быстром переходе между предложениями **никогда не показывается устаревшее предложение**: предыдущие запросы отменяются (`promise.abort()` у thunk + `signal` в axios). Отменённый запрос **не показывает ошибку** пользователю.
- Ф: при ошибке сети - сообщение и кнопка «Повторить» (`retry`). Повтор - не больше `[retries]` раз автоматически с паузой, затем только вручную.
- Т: первый запрос отвечает позже второго - на экране данные второго; отмена при размонтировании; отменённый запрос не переводит хук в `error`; 404 → `not-found`; автоповтор нужное число раз.
- П: что такое гонка запросов; покажите её вживую (см. «Как увидеть гонку» в `README.md`); почему отмена в cleanup, а не в обработчике клика; как вы отличаете отмену от настоящей ошибки.

**H3. `useOutsideClick(ref, handler, isActive)` и `useKeydown(key, handler, isActive)` - меню сортировки**
- Ф: меню сортировки закрывается по клику вне него и по Escape. Подписки на `document` есть **только пока меню открыто**. Клавиатура: стрелки вверх и вниз двигают выделение по пунктам, Enter выбирает.
- Т: клик внутри - не закрывает, снаружи - закрывает; Escape закрывает; стрелки и Enter; после закрытия и размонтирования обработчики сняты; новый `handler` на каждом рендере **не** пересоздаёт подписку.
- П: почему подписка не должна пересоздаваться при новом `handler` и как вы это решили; разница между `mousedown` и `click` для «клика снаружи».

**H4. `useUrlState(name, defaultValue, parse)` - сортировка и поиск в адресной строке**
- Ф: выбранная сортировка и строка поиска хранятся в query-параметрах (`/?sort=price-asc&q=house`) через `useSearchParams` React Router. Ссылку можно скопировать и открыть в другой вкладке - откроется то же состояние. Кнопки «назад» и «вперёд» в браузере переключают состояние. Некорректное значение (`?sort=abc`) - значение по умолчанию, без ошибки.
- Ф: ввод в поиске **не** создаёт запись в истории на каждую букву (`replace`), смена сортировки - создаёт (`push`).
- Т: чтение из URL, запись в URL, некорректное значение, `replace` против `push` (тест с `MemoryRouter`).
- П: где теперь источник правды для сортировки - в URL или в Redux - и почему не в обоих; что будет, если хранить и там, и там.

### Часть 2. Внешние API, хранилище, формы и современный React

**H5. `useYandexMap(containerRef, city, offers, activeOfferId)` - карта на Яндекс Картах**
- Ф: карта Leaflet заменена на Яндекс Карты (JS API 3.0, ключ - в `.env.local`, в репозиторий не попадает, см. `SETUP.md`). Скрипт API грузится **один раз** на всё приложение, даже если две карты монтируются одновременно. Карта создаётся один раз, при смене города меняется центр, при наведении на карточку маркер меняет цвет (на странице предложения - нет, как в ТЗ). При уходе со страницы карта уничтожается.
- Ф: если ключ не задан или скрипт не загрузился - вместо карты сообщение, приложение работает.
- Т: мок API карт: скрипт загружается один раз при двух одновременных вызовах; карта создаётся один раз; при смене `activeOfferId` обновляются только маркеры, а не карта; при размонтировании вызывается `destroy`; ошибка загрузки → сообщение.
- П: почему в `StrictMode` эффект срабатывает дважды и что было бы с картой без cleanup; почему инициализация карты и обновление маркеров - разные эффекты; как сделать загрузку скрипта «один раз».

**H6. `usePersistentState<T>(key, initialValue, validate)` - черновик отзыва**
- Ф: текст и оценка в форме отзыва сохраняются в `localStorage` под ключом `[prefix]-draft-<offerId>` и восстанавливаются после перезагрузки. После успешной отправки черновик удаляется. Если открыть то же предложение во второй вкладке, изменения из первой подхватываются (событие `storage`).
- Ф: `validate` - функция-проверка типа (`(value: unknown) => value is T`). Битый JSON или данные не той формы → `initialValue`, без падения. Ошибка записи (переполнено хранилище, приватный режим) не роняет приложение.
- Т: восстановление; запись; битый JSON; данные не той формы; ошибка `setItem`; событие `storage`; смена `key` (другой offerId) не утаскивает чужой черновик.
- П: зачем ленивая инициализация `useState(() => ...)`; что происходит при смене `key` в вашем коде; почему событие `storage` не приходит во вкладку, которая сама записала.

**H7. `usePagedList<T>(items, pageSize)` + `useScrollRestoration(key)` - подгрузка карточек**
- Ф: на главной список показывается порциями по `[pageSize]` карточек, следующая порция появляется, когда пользователь докрутил до конца (`IntersectionObserver`). При смене города, сортировки или поиска показ начинается с первой порции.
- Ф: пользователь докрутил до третьей порции, открыл предложение, нажал «назад» - видит **те же три порции и то же место прокрутки**.
- Т: первая порция; следующая при срабатывании наблюдателя (мок); сброс при смене `items`; отключение наблюдателя при размонтировании; восстановление числа порций и прокрутки.
- П: способы сбросить состояние при смене входных данных (`key`, эффект, вычисление при рендере) и чем они отличаются; почему восстанавливать прокрутку надо после отрисовки списка, а не сразу.

**H8. `useReviewForm(offerId)` на `useReducer` - форма отзыва**
- Ф: состояние формы - конечный автомат на `useReducer`: `editing → submitting → success | error`. Валидация: оценка 1-5, текст 50-300 символов; кнопка неактивна, пока данные невалидны; во время отправки форма заблокирована; при ошибке - сообщение и данные **не теряются**; после успеха - очистка. Черновик хранится через ваш `usePersistentState` (H6).
- Ф: повторное нажатие «Submit» во время отправки ничего не делает (нет двойной отправки).
- Т: **редьюсер тестируется отдельно** как чистая функция (все переходы, недопустимые переходы игнорируются); хук - отправка, ошибка, повторная отправка.
- П: почему `useReducer`, а не пять `useState`; что значит «недопустимый переход» и как ваш редьюсер его обрабатывает.

**M1. `useEffectEvent` в H3** (React 19.2)
- Ф: отдельным PR внутри `useOutsideClick` и `useKeydown` ваш способ хранить актуальный обработчик (`useRef`) заменён на `useEffectEvent`. Тесты H3 не менялись и зелёные (О14).
- П: что `useEffectEvent` делает за вас; почему его результат не кладут в зависимости эффекта и почему его нельзя вызывать при рендере и передавать в дочерние компоненты.

**M2. `useActionState` и `useFormStatus` в форме отзыва** (React 19.0)
- Ф: отдельным PR форма отзыва переведена на `<form action={...}>` + `useActionState`; кнопка «Submit» - отдельный компонент, который узнаёт о статусе отправки через `useFormStatus`. Отправка по-прежнему идёт через ваш thunk Redux. Тесты H8 на поведение формы зелёные.
- Ф: в `JOURNAL.md` - сравнение: что стало проще, что сложнее, что осталось от вашего редьюсера и почему. Если решили, что ваш автомат лучше, - аргументируйте, но PR с `useActionState` всё равно должен быть в истории.
- П: что получает функция-действие первым аргументом; откуда `useFormStatus` знает о статусе, если ему ничего не передали; почему `isPending` не надо хранить самому.

**M3. `<ViewTransition>` - анимация переходов** (React 19.3)
- Ф: смена города на главной и переход на страницу предложения анимированы через `<ViewTransition>` и `startTransition`. Ввод в поле поиска **не** анимируется (это срочное обновление). Направление анимации зависит от того, вперёд или назад идёт переход (`addTransitionType`).
- Ф: свой механизм анимации переходов React Router (`viewTransition`, `useViewTransitionState`) **не используется** - в React Router 8.5 он устарел.
- П: почему анимируются только обновления в переходе, а срочные - нет; что произойдёт, если два элемента на странице получат одинаковое `name`.

**M4. `<title>` и `<meta>` в компонентах страниц** (React 19.0)
- Ф: у каждой страницы свой заголовок вкладки: `Six Cities - Amsterdam`, `Six Cities - <название предложения>`, `Six Cities - Favorites (3)`, `Six Cities - Login`, `Six Cities - 404`. Заголовок задаётся тегом `<title>` прямо в компоненте страницы, без библиотек (`react-helmet` и подобные запрещены).
- Т: тест, что после загрузки предложения `document.title` содержит его название.
- П: как React поднимает `<title>` из глубины дерева в `<head>`; что будет, если `<title>` отрисован в двух компонентах одновременно.

### Часть 3. Оптимистичные обновления, производительность и React Router 8

**H9. `useOptimisticFavorite(offerId, isFavorite)` - оптимистичное избранное**
- Ф: кнопка «Избранное» меняет иконку **сразу**, не дожидаясь сервера, счётчик в шапке тоже меняется сразу. Если сервер ответил ошибкой - состояние откатывается и показывается сообщение. Быстрые повторные клики не ломают состояние: итог всегда совпадает с последним кликом пользователя и с сервером.
- Т: успех; ошибка → откат; два быстрых клика при медленном сервере → итог корректный; неавторизованный → переход на `/login` без запроса.
- П: что такое оптимистичное обновление и когда его нельзя применять; как вы решили проблему быстрых повторных кликов.

**H10. `useRecentlyViewed()` - недавно просмотренные**
- Ф: на главной под списком блок «Recently viewed» - последние `[recentCount]` открытых предложений, новые сверху, без дублей, переживает перезагрузку. Хук **построен на вашем `usePersistentState`** (композиция хуков), а не копирует его код.
- Т: порядок, отсутствие дублей, ограничение длины, переживает перезагрузку.
- П: что такое композиция хуков; показывают ли два компонента с этим хуком на одной странице одно и то же, и если нет - как починить.

**H11. `useOnlineStatus()` на `useSyncExternalStore` + замер производительности**
- Ф: при пропаже сети (DevTools → Offline) сверху появляется плашка «Нет соединения», при возврате исчезает, а `useOfferLoader` повторяет упавший запрос. Реализовано через `useSyncExternalStore`, а не связкой `useEffect` + `useState`.
- Ф: файл `PERF.md` - замер главной страницы в React DevTools Profiler **до и после** оптимизации (`memo`, `useMemo`, `useCallback`): сценарии «сменить город», «сменить сортировку», «навести на карточку», с цифрами и скриншотами. Оптимизация только там, где замер показал лишние рендеры. Каждая оптимизация, которая **не дала** эффекта, тоже описана - и убрана из кода.
- Т: тест хука с переключением `navigator.onLine` и событиями `online` / `offline`.
- П: чем `useSyncExternalStore` лучше связки «эффект + состояние» для внешних источников; почему `useCallback` без `memo` у дочернего компонента часто бесполезен.

**M5. `useOptimistic` в H9** (React 19.0)
- Ф: отдельным PR внутренняя реализация `useOptimisticFavorite` переведена на `useOptimistic`. Тесты H9 не менялись и зелёные (О14), в том числе тест на быстрые повторные клики.
- П: почему `useOptimistic` работает только внутри перехода или действия; как он «откатывается» сам и почему вам больше не нужно хранить предыдущее значение.

**M6. `<Activity>` - главная страница не теряет состояние** (React 19.2)
