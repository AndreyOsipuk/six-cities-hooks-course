# Курсовой проект: «Шесть городов» - свои хуки

Вы уже сделали «Шесть городов». В курсовом проекте вы **дорабатываете своё приложение**: добавляете новые возможности, и каждая из них должна быть реализована **через собственный хук**, написанный с нуля.

Цель - не «чтобы работало», а чтобы вы **понимали, как работают хуки**: когда срабатывает эффект, зачем нужен cleanup, откуда берутся гонки запросов, лишние рендеры и утечки подписок. Поэтому на защите главное - не код, а то, как вы его объясняете.

- Критерии оценки - [CRITERIA.md](CRITERIA.md) (прочитайте целиком до начала работы)
- Настройка окружения и Яндекс Карты - [SETUP.md](SETUP.md)
- Журнал разработки (заполняете по ходу) - [JOURNAL.md](JOURNAL.md)

## Как работаем

1. **Один хук - одна ветка - один Pull Request.** Ветку называете `hook/<имя-хука>`, например `hook/use-debounced-value`.
2. В PR заполняете шаблон: что сделано, какой баг словили, как проверили. Шаблон подставится сам (файл `.github/pull_request_template.md` - скопируйте его в свой репозиторий).
3. Коммитите **маленькими шагами по ходу работы**: «хук без отмены», «нашёл гонку», «добавил отмену», «тест на отмену». Один огромный коммит с готовым хуком - нарушение критерия О3.
4. После каждого хука - запись в `JOURNAL.md`.
5. Мерж в `main` - только когда `npm run lint` и `npm test` зелёные.

### Про ИИ-ассистентов

Оценивается **ваше понимание**, а не наличие кода. На защите я открываю любую строку вашего хука и спрашиваю, зачем она, ломаю хук и прошу починить, даю фрагмент кода и прошу предсказать порядок вывода в консоль. Код, который вы не можете объяснить, не засчитывается - неважно, кто его написал. Поэтому если что-то непонятно - спросите на занятии или в чате группы, а не копируйте.

## Подсказки

### Как увидеть гонку запросов (для H2)

Сервер академии отвечает быстро, поэтому гонку «на глаз» не видно. Добавьте в свой `axios`-клиент **только для режима разработки** случайную задержку ответа:

```ts
// src/services/api.ts - внутри createAPI(), после создания экземпляра axios
if (import.meta.env.DEV && import.meta.env.VITE_API_JITTER === 'true') {
  api.interceptors.response.use(
    (response) =>
      new Promise((resolve) => {
        setTimeout(() => resolve(response), Math.random() * 2000);
      })
  );
}
```

Запустите с `VITE_API_JITTER=true npm start`, откройте предложение и быстро покликайте по карточкам «неподалёку». Если на экране иногда остаётся не то предложение, на которое вы кликнули последним, - вы нашли гонку. Опишите это в журнале **до** того, как начнёте чинить.

### Как увидеть двойной запуск эффектов (для H4)

В режиме разработки `<React.StrictMode>` монтирует компонент, размонтирует и монтирует снова. Если у карты нет cleanup, вы увидите две карты в одном контейнере или ошибку от API. Не убирайте `StrictMode`, чтобы «починить» - чините хук.

### Как замерить рендеры (для H8)

React DevTools → вкладка **Profiler** → запись → смените город / сортировку / наведите на карточку → остановите запись. Сохраните скриншот «до», оптимизируйте, сделайте тот же сценарий и скриншот «после». Цифры (сколько компонентов перерисовалось, сколько мс) - в `PERF.md`.
