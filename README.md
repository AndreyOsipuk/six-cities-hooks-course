# Курсовой проект «Шесть городов»

За время курса вы **с нуля соберёте полноценное приложение** «Шесть городов» - сервис поиска жилья в аренду: шесть городов, список предложений с картой, сортировка, страница предложения с отзывами, вход, избранное. Приложение адаптивное: работает на телефоне, планшете и десктопе. Что это за приложение, какие в нём страницы и что на каждой - в [PROJECT.md](PROJECT.md).

Проект собирается **по этапам, параллельно с программой курса**: прошли маршрутизацию - добавили маршруты, прошли Redux - перевели состояние в Redux, и так далее. На каждом этапе две части:

1. **Базовая функциональность** - то, что должно работать в приложении по ТЗ.
2. **Свои хуки и современный React** - задачи, которые на этом этапе решаются собственным хуком, написанным с нуля (пункты H), или встроенными средствами React 19 и React Router 8 (пункты M).

Цель - рабочий проект **и** понимание того, как он устроен: когда срабатывает эффект, зачем нужен cleanup, откуда берутся гонки запросов, лишние рендеры и утечки подписок.

### Современный React: что он делает за вас

| Пункт | Что делаем | Сравниваем с | Этап |
|-------|-----------|--------------|:-:|
| M1 `useEffectEvent` | Заменяем им `useRef` с актуальным обработчиком | H3 | 6 |
| M2 `useActionState`, `useFormStatus` | Переводим форму отзыва на `<form action>` | H8 | 7 |
| M3 `<ViewTransition>` | Анимируем смену города и переход на предложение | - | 6 |
| M4 `<title>` в компонентах | Свой заголовок вкладки на каждой странице | - | 2 |
| M5 `useOptimistic` | Заменяем им свою логику отката в избранном | H9 | 8 |
| M6 `<Activity>` | Главная не размонтируется при переходе на предложение | H7 | 9 |
| M7 React Compiler | Третий замер в `PERF.md`: вручную против компилятора | H11 | 9 |

Правило для M1, M2, M5: **сначала принимается ваша версия, потом отдельный PR переводит её на встроенный API, а тесты не меняются**. Если после замены тест упал, значит встроенный API ведёт себя не так, как вы думали, - это и есть самое интересное место для журнала.

## Как работаем

1. **Одна задача - одна ветка - один Pull Request.** Базовая функциональность этапа - ветки `stage-<номер>/<что>`, например `stage-3/routing`. Свои хуки - `hook/<имя-хука>`, например `hook/use-debounced-value`. Обновление стека - `stack/upgrade`. Пункты M - `modern/<пункт>`, например `modern/use-effect-event`.
2. **Сначала воспроизведите баг тестом.** Нашли проблему - коммит с падающим тестом, затем коммит с исправлением (критерий О4).
3. Коммитите **маленькими шагами**: «хук без отмены», «тест на гонку (красный)», «отмена запроса», «тест на размонтирование». Один огромный коммит с готовым хуком - нарушение критерия О3.
4. В PR заполняете шаблон: что сделано, какой баг словили, как проверили.
5. После каждого хука - запись в `JOURNAL.md`, строка в `src/hooks/README.md`, ответы на относящиеся к нему вопросы из `QUESTIONS.md`.
6. Мерж в `main` - только когда `npm run lint` и `npm test` зелёные.

## Подсказки

### Как увидеть гонку запросов (H2, H9)

Сервер академии отвечает быстро, поэтому гонку «на глаз» не видно. Добавьте в свой `axios`-клиент **только для режима разработки** случайную задержку ответа:

```ts
// src/services/api.ts - внутри createAPI(), после создания экземпляра axios
if (import.meta.env.DEV && import.meta.env.VITE_API_JITTER === 'true') {
  api.interceptors.response.use(
    (response) =>
      new Promise((resolve) => {
        setTimeout(() => resolve(response), Math.random() * 2000);
      })
  );
}
```

Запустите с `VITE_API_JITTER=true npm start`, откройте предложение и быстро покликайте по карточкам «неподалёку». Если на экране иногда остаётся не то предложение, на которое вы кликнули последним, - вы нашли гонку. Опишите это в журнале и напишите красный тест **до** того, как начнёте чинить. Для H9 - так же быстро покликайте по «Избранному».

### Как увидеть двойной запуск эффектов (H5)

В режиме разработки `<React.StrictMode>` монтирует компонент, размонтирует и монтирует снова. Если у карты нет cleanup, вы увидите две карты в одном контейнере или ошибку от API. Не убирайте `StrictMode`, чтобы «починить», - чините хук.

### Как увидеть ошибку сервера (H2, H8, H9)

DevTools → Network → правый клик по запросу → **Block request URL**. Или Network → Throttling → **Offline**. Так проверяются кнопка «Повторить», откат избранного и сохранение данных формы при ошибке.

### Как проверить адаптив (О15, H12)

Вёрстка академии - только для десктопа, адаптив делаете сами (требования - [PROJECT.md](PROJECT.md), раздел 10). Проверка: DevTools → режим устройства, ширины 320, 375, 768, 1024, 1440. На своём телефоне: `npm start -- --host` и адрес из вывода Vite в браузере телефона (одна сеть Wi-Fi). Самая частая ошибка - горизонтальная прокрутка на 320 px из-за фиксированной ширины 1144 px из вёрстки.

### Как замерить рендеры (H11, M7)

React DevTools → вкладка **Profiler** → шестерёнка → включите «Record why each component rendered» → запись → сценарий → стоп. Скриншот «до», оптимизация, тот же сценарий, скриншот «после». Цифры - в `PERF.md`.

Второй инструмент - Chrome DevTools (или Яндекс Браузер) → вкладка **Performance**: с React 19.2 там есть дорожки React - **Scheduler** (какие обновления срочные, какие - переходы) и **Components** (какие компоненты монтировались и рендерились). Для M3 и M7 скриншот этих дорожек обязателен.

После включения компилятора (M7) компоненты, которые он оптимизировал, отмечены в React DevTools значком **Memo ✨**.

### Как обновлять стек (H0)

В шаблоне почти нет кода, поэтому обновление - это в основном замена версий и конфигов. Но всё равно не обновляйте всё одной командой. Порядок, при котором проще всего найти, что сломалось:

1. TypeScript, Vite, Vitest, `@vitejs/plugin-react`;
2. React и React DOM 18 → 19, `@types/react`;
3. Redux Toolkit 1 → 2 и `react-redux`;
4. React Router 6 → 8 (через руководства по переходу на v7 и v8, флаги `future` включайте по одному);
5. ESLint и `eslint-plugin-react-hooks` 7 - последним, потому что он найдёт ошибки в уже обновлённом коде.

После каждого шага: `npm run lint`, `npm test`, `npm start` - и коммит.
