# Курсовой проект: «Шесть городов» - свои хуки

Вы уже сделали «Шесть городов». В курсовом проекте вы **дорабатываете своё приложение**: добавляете новые возможности, и каждая из них должна быть реализована **через собственный хук**, написанный с нуля.

Цель - не «чтобы работало», а чтобы вы **понимали, как работают хуки**: когда срабатывает эффект, зачем нужен cleanup, откуда берутся гонки запросов, лишние рендеры и утечки подписок. Поэтому на защите главное - не код, а то, как вы его объясняете.

## Как работаем

1. **Один хук - одна ветка - один Pull Request.** Ветку называете `hook/<имя-хука>`, например `hook/use-debounced-value`.
2. **Сначала воспроизведите баг тестом.** Нашли проблему - коммит с падающим тестом, затем коммит с исправлением (критерий О4).
3. Коммитите **маленькими шагами**: «хук без отмены», «тест на гонку (красный)», «отмена запроса», «тест на размонтирование». Один огромный коммит с готовым хуком - нарушение критерия О3.
4. В PR заполняете шаблон: что сделано, какой баг словили, как проверили.
5. После каждого хука - запись в `JOURNAL.md`, строка в `src/hooks/README.md`, ответы на относящиеся к нему вопросы из `QUESTIONS.md`.
6. Мерж в `main` - только когда `npm run lint` и `npm test` зелёные.

## Подсказки

### Как увидеть гонку запросов (H2, H9)

Сервер академии отвечает быстро, поэтому гонку «на глаз» не видно. Добавьте в свой `axios`-клиент **только для режима разработки** случайную задержку ответа:

```ts
// src/services/api.ts - внутри createAPI(), после создания экземпляра axios
if (import.meta.env.DEV && import.meta.env.VITE_API_JITTER === 'true') {
  api.interceptors.response.use(
    (response) =>
      new Promise((resolve) => {
        setTimeout(() => resolve(response), Math.random() * 2000);
      })
  );
}
```

Запустите с `VITE_API_JITTER=true npm start`, откройте предложение и быстро покликайте по карточкам «неподалёку». Если на экране иногда остаётся не то предложение, на которое вы кликнули последним, - вы нашли гонку. Опишите это в журнале и напишите красный тест **до** того, как начнёте чинить. Для H9 - так же быстро покликайте по «Избранному».

### Как увидеть двойной запуск эффектов (H5)

В режиме разработки `<React.StrictMode>` монтирует компонент, размонтирует и монтирует снова. Если у карты нет cleanup, вы увидите две карты в одном контейнере или ошибку от API. Не убирайте `StrictMode`, чтобы «починить», - чините хук.

### Как увидеть ошибку сервера (H2, H8, H9)

DevTools → Network → правый клик по запросу → **Block request URL**. Или Network → Throttling → **Offline**. Так проверяются кнопка «Повторить», откат избранного и сохранение данных формы при ошибке.

### Как замерить рендеры (H11)

React DevTools → вкладка **Profiler** → шестерёнка → включите «Record why each component rendered» → запись → сценарий → стоп. Скриншот «до», оптимизация, тот же сценарий, скриншот «после». Цифры - в `PERF.md`.
