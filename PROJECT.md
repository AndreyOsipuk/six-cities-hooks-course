# Проект «Шесть городов»: что это за приложение

«Шесть городов» - сервис для поиска жилья в аренду на короткий срок. Пользователь выбирает один из шести городов (Paris, Cologne, Brussels, Amsterdam, Hamburg, Dusseldorf), смотрит предложения списком и на карте, сортирует их, открывает подробную страницу, добавляет в избранное и оставляет отзывы.

Приложение собирается с нуля по этапам - см. [TASKS.md](TASKS.md).

Исходные материалы:

- **Стартовый шаблон** - репозиторий проекта, который академия создаёт вам при записи на курс. В нём папка `markup/` с вёрсткой всех страниц и состояний, стили, картинки, шрифты и настроенный Vite.
- **Вёрстка** - это и есть макет: `main.html` (главная), `main-empty.html` (главная без предложений), `offer.html` (предложение, пользователь вошёл), `offer-not-logged.html` (предложение, гость), `login.html` (вход), `favorites.html` (избранное), `favorites-empty.html` (пустое избранное). Страницы 404 в вёрстке нет - её оформление на ваше усмотрение.
- **Полное ТЗ академии** - в личном кабинете: раздел «Проекты» → «Шесть городов».
- **API сервера** - https://14.design.htmlacademy.pro/spec/six-cities

Ниже - описание своими словами, сведённое в одном месте. Пометка **«Сверх ТЗ:»** показывает, что в нашем задании добавляется к ТЗ академии на этой странице (подробно - в [TASKS.md](TASKS.md)).

## 1. Страницы и доступ

| Страница | Адрес | Кто видит | Если доступа нет |
|----------|-------|-----------|------------------|
| Главная | `/` | все | - |
| Предложение | `/offer/:id` | все | несуществующий `id` → страница 404 |
| Вход | `/login` | только неавторизованные | авторизованного перенаправляет на `/` |
| Избранное | `/favorites` | только авторизованные | неавторизованного перенаправляет на `/login` |
| Не найдено | любой другой адрес | все | - |

**Сверх ТЗ:** на главной в адресе появляются параметры сортировки и поиска - `/?sort=price-asc&q=house` (H4).

## 2. Шапка (на всех страницах)

- Логотип - ссылка на главную.
- **Не авторизован:** ссылка «Sign in» на `/login`.
- **Авторизован:** email пользователя, рядом - число предложений в избранном; клик по email ведёт на `/favorites`. Кнопка «Sign out» завершает сеанс.
- Число избранного меняется **сразу** при добавлении или удалении на любой странице.

**Сверх ТЗ:** при пропаже сети над шапкой - плашка «Нет соединения» (H11). Заголовок вкладки браузера свой на каждой странице (M4).

## 3. Главная страница `/`

### 3.1. Список городов

- Шесть вкладок: Paris, Cologne, Brussels, Amsterdam, Hamburg, Dusseldorf. Сервер работает только с этими городами.
- При первом открытии выбран **Paris**.
- При смене города обновляются и список, и карта.

### 3.2. Заголовок списка

Число предложений в выбранном городе: `312 places to stay in Amsterdam`.

### 3.3. Сортировка

Выпадающее меню «Sort by» с вариантами:

| Вариант | Порядок |
|---------|---------|
| Popular (по умолчанию) | как пришло с сервера |
| Price: low to high | от дешёвых к дорогим |
| Price: high to low | от дорогих к дешёвым |
| Top rated first | от высокого рейтинга к низкому |

Меню закрыто по умолчанию, открывается кликом по текущему варианту, закрывается после выбора. После выбора список перерисовывается.

**Сверх ТЗ:** меню закрывается по клику снаружи и по Escape, управляется стрелками (H3); выбранная сортировка хранится в адресе (H4); над списком - поиск по названию (H1).

### 3.4. Карточка предложения

| Элемент | Что показывает |
|---------|----------------|
| Фото | превью жилья |
| Метка «Premium» | только у премиальных предложений |
| Цена | за ночь, всегда в евро: `€120 / night` |
| Кнопка «Избранное» | прозрачная - не в избранном, синяя - в избранном; клик переключает. Неавторизованного перенаправляет на `/login` |
| Рейтинг | закрашенные звёзды из 5, округление до целого: 3.1 → 3, 4.5 → 5 |
| Название | ссылка на `/offer/:id` |
| Тип | apartment, room, house или hotel |

**Сверх ТЗ:** избранное переключается мгновенно, с откатом при ошибке (H9, M5); карточки подгружаются порциями при прокрутке (H7).

### 3.5. Карта

- Все предложения города - синие маркеры.
- Наведение на карточку в списке - маркер этого предложения становится **оранжевым** (только на главной).

**Сверх ТЗ:** карта Leaflet заменяется на **Яндекс Карты** (H5).

### 3.6. Пустой город

Если предложений нет - надпись «No places to stay available», вместо карты - статичная картинка (см. вёрстку в `markup/`).

### 3.7. Что добавляется на главную сверх ТЗ

- поле «Search by title» над списком (H1);
- блок «Recently viewed» под списком - последние открытые предложения (H10);
- анимация при смене города (M3);
- при возврате со страницы предложения - тот же город, поиск, порции и место прокрутки (H7, M6).

## 4. Страница предложения `/offer/:id`

### 4.1. Основная информация

| Элемент | Правило |
|---------|---------|
| Фотографии | не больше 6; если больше - первые 6 |
| Метка «Premium» | только у премиальных |
| Название | например «Beautiful & luxurious studio at great location» |
| Кнопка «Избранное» | как на карточке |
| Рейтинг | звёзды (округление до целого) **и** число без округления: `4.8` |
| Тип | Apartment, Room, House, Hotel - с заглавной буквы |
| Спальни | `1 Bedroom` / `3 Bedrooms` - склонение по числу |
| Гости | `Max 1 adult` / `Max 4 adults` - склонение по числу |
| Цена | за ночь, в евро |
| Удобства | список: Wifi, Heating, Kitchen, Cable TV и т. д. |
| Хозяин | аватар, имя; у Pro - звёздочка у аватара и подпись «Pro» |
| Описание | текст |

### 4.2. Отзывы

- В заголовке - общее число: `Reviews · 12`.
- Показывается **не больше 10**, новые сверху.
- В каждом отзыве: аватар и имя автора, оценка звёздами, дата в формате «Месяц Год» (`April 2019`), текст.

### 4.3. Форма отзыва

- Видна **только авторизованным**.
- Оценка от 1 до 5 - выбором звёзд. Текст - от 50 до 300 символов.
- Кнопка «Submit» неактивна, пока не выбрана оценка и длина текста не подходит.
- Во время отправки заблокированы и кнопка, и вся форма. Разблокируются после успеха или ошибки.
- После успеха форма очищается. При ошибке - сообщение пользователю (вид - на ваше усмотрение).
- Отзывов можно оставлять сколько угодно.

**Сверх ТЗ:** черновик формы переживает перезагрузку и синхронизируется между вкладками (H6); форма - конечный автомат на `useReducer` (H8), затем `useActionState` (M2).

### 4.4. Предложения неподалёку

- Под отзывами - карта: **3 соседних предложения** синими маркерами + **текущее** оранжевым, всего 4 маркера. Наведение на карточки здесь цвет не меняет.
- Под картой - карточки этих трёх предложений, такие же, как на главной.

**Сверх ТЗ:** загрузка без гонок при быстром переходе между предложениями, с повтором при ошибке (H2), затем через `loader` React Router (M8); анимация перехода (M3).

---

## 5. Страница входа `/login`

- Поля: email и пароль. Регистрации нет - подходят любые непустые значения.
- Email - поле с `type="email"`.
- Пароль - минимум одна буква **и** одна цифра.
- Справа - кнопка с названием **случайного** города из шести. Клик ведёт на главную с этим городом.
- Авторизованного пользователя сразу перенаправляет на главную.

---

## 6. Избранное `/favorites`

- Только для авторизованных. Данные **всегда** загружаются с сервера отдельным запросом.
- Предложения сгруппированы по городам.
- Кнопка «Избранное» на карточке удаляет предложение - оно сразу исчезает из списка, число в шапке уменьшается.
- Если избранного нет - «Nothing yet saved» (см. вёрстку).

---

## 7. Страница 404

Любой несуществующий адрес. Минимум - текст «404 Not Found» и ссылка на главную. Приложение не должно падать с ошибкой.

---

## 8. Общие правила

- Активные элементы (выбранный город, выбранная сортировка, избранное) получают свои классы оформления - примеры в `markup/`.
- Сервер недоступен - пользователь видит понятное сообщение, а не пустую страницу или ошибку в консоли.
- Все данные приходят с сервера, ничего не захардкожено.

## 9. Сервер

- Базовый адрес: `https://14.design.htmlacademy.pro/six-cities`
- Спецификация (OpenAPI): https://14.design.htmlacademy.pro/spec/six-cities
- Данные - JSON. На сервере 120 предложений, по 20 на каждый город.
- **Авторизация** по токену: `POST /login` возвращает `token`, дальше он передаётся в каждом запросе в заголовке `X-Token`. В SPA токен хранится в `localStorage` под ключом `six-cities-token`.

### 9.1. Маршруты

| Метод | Путь | Нужен токен | Что делает | Ответы |
|-------|------|:-:|------------|--------|
| GET | `/offers` | - | Все предложения (краткие) | 200 |
| GET | `/offers/{offerId}` | - | Одно предложение (полное) | 200, 404 |
| GET | `/offers/{offerId}/nearby` | - | Предложения неподалёку | 200, 404 |
| GET | `/favorite` | да | Избранное пользователя | 200, 401 |
| POST | `/favorite/{offerId}/{status}` | да | `status`: 1 - добавить, 0 - удалить | 200, 201, 400, 401, 404, 409 |
| GET | `/comments/{offerId}` | - | Отзывы предложения | 200, 404 |
| POST | `/comments/{offerId}` | да | Добавить отзыв `{ comment, rating }` | 201, 400, 401, 404 |
| GET | `/login` | да | Проверить, авторизован ли пользователь | 200, 401 |
| POST | `/login` | - | Войти `{ email, password }` | 200, 400 |
| DELETE | `/logout` | да | Выйти | 204 |

### 9.2. Данные

**Краткое предложение** (в списках):

```ts
type OfferPreview = {
  id: string;
  title: string;
  type: 'apartment' | 'room' | 'house' | 'hotel';
  price: number;
  previewImage: string;
  city: City;
  location: Location;
  isFavorite: boolean;
  isPremium: boolean;
  rating: number;
};
```

**Полное предложение** (страница `/offer/:id`) - всё то же, кроме `previewImage`, плюс:

```ts
type Offer = Omit<OfferPreview, 'previewImage'> & {
  description: string;
  bedrooms: number;
  goods: string[];
  host: Host;
  images: string[];
  maxAdults: number;
};
```

**Остальное:**

```ts
type Location = { latitude: number; longitude: number; zoom: number };
type City = { name: string; location: Location };
type Host = { name: string; avatarUrl: string; isPro: boolean };

type Review = {
  id: string;
  date: string;       // ISO-строка
  user: Host;
  comment: string;
  rating: number;
};

type AuthInfo = Host & { email: string; token: string };
```

Внимание для Яндекс Карт: сервер отдаёт `latitude` и `longitude` отдельными полями, а Яндекс Карты ждут массив **`[longitude, latitude]`** - долгота первой.

## 10. Требования к коду

Требования из критериев академии - действуют для всего проекта.

**Работоспособность**
- ТЗ выполнено целиком, в консоли нет необработанных ошибок, приложение одинаково работает в актуальных браузерах.

**Стиль и именование**
- Код проходит ESLint (конфиг академии).
- Переменные, параметры, свойства, методы - `camelCase`, со строчной буквы, английские существительные.
- Константы - `UPPER_CASE`. Классы и перечисления (`enum`) - с заглавной буквы, существительные.
- Массивы - во множественном числе (`offers`, `reviews`). Функции и методы - с глаголом (`getOffers`, `sortByPrice`).

**Архитектура**
- Адресная строка - только React Router.
- Глобальное состояние - только Redux.

**Файлы и структура**
- В репозитории только файлы проекта: никаких неиспользуемых модулей и закомментированного кода.
- Весь TS/TSX - в `src`. Компоненты - в `src/components`, страницы - в `src/pages`, HOC - в `src/hocs`, свои хуки - в `src/hooks`.
- Имена файлов - строчными через дефис (`offer-card.tsx`). Главный файл папки называется как папка: `offer-card/offer-card.tsx` или `index.ts` для реэкспорта.
